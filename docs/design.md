# agent-elapsed 设计文档

日期：2026-10-22
范围：v1（本文是实现依据；数学勘误与准确性边界见 accuracy-audit.md）

2026-10-23 增量：用户要求以任务 hook 驱动宿主 TUI / 原生 UI 内的长任务组件，组件没有网页。运行时展示及状态管理以 [嵌入组件设计](embedded-widget.md) 为准；本文件的自包含 HTML 仅保留作离线复盘。数学勘误、校准修正和准确性边界以 [数学审计](accuracy-audit.md) 为准；未校准运行时只展示已用时。

## 1. 这是什么

一个轻量组件。当 Agent 接到用户交代的任务、开始干活的同时，它**并行**给出一个大约用时区间（例如"6–14 分钟"）；任务结束后，它把预估和实际耗时画在同一根轴上，并据此慢慢把预估变准。

发起方式来自用户的两个要求，二者共同决定了整个架构：

1. 预估要**并行**产生，且自身**不能消耗太多 token、不能算太久**。
2. 组件**本身必须轻量**；前期数学研究的广度不等于组件的体积。

### 1.1 核心设计立场

一个 LLM 直接回答"这任务要多久"，给的是**叙事性猜测**：它没有可被数据修正的参数，因此永远不会变准。所以把预估拆成不可混用的两半：

- **语义部分**（小模型一次性分类调用）：任务描述 → 特征标签。只输出分类档位，**不输出数字**。
- **算术部分**（纯函数，零 token，毫秒级）：特征标签 → 分位数区间。

算术层的参数全部从真实遥测里估计，因此"预估"这件事是可校准、可证伪、可收敛的。

### 1.2 目标

- 任务开始时给出 P50/P90 用时区间，以及时间花在哪些操作类型上的分解。
- 任务结束后给出预估与实际的对齐视图。
- 累积数据后自动变准，且**每次模型更新都必须先通过验收门才能上线**。
- 组件运行时零拟合：读一张常数表 + 一次蒙特卡洛采样。

### 1.3 非目标（v1 明确不做）

- 倒计时、进度条、运行中途刷新"还剩几分钟"。v1 只在任务开始时估一次。
  理由：中途更新等于维护第二个模型和第二套校准判据，这是本项目最大的范围膨胀风险。
- 事前"这任务能不能做"的可行性判断。
- 成本/token 用量估算（只做时间）。
- 在线/自动重拟合；每次拟合跑超参搜索网格；层次模型的全贝叶斯 MCMC。
- 鞍点近似（蒙特卡洛已正确，属性能优化）。
- 多环境常数表的管理界面（v1 只落地当前环境一组，数据结构预留分组）。

## 2. 架构与边界

```
                      任务描述
                         │
                         ├─→ 小模型分类（1 次调用，无工具，约 60–90 输出 token）
                         │        │ g_pred（分类档位 + top-2 软概率）
                         │        ▼
                         │   ┌─────────────────────┐
                         │   │   组件运行时（纯函数） │  ← constants.json（只读）
                         │   └─────────────────────┘
                         │        │ {p50, p90, contributions, calibrating, fit_id, seed}
                         │        ├─→ 可视化组件（自包含 HTML，JSON 由离线脚本内联注入）
                         │        ▼
                         │   主 Agent 干活（并行，互不阻塞）
                         │        │
                         ▼        ▼
                     events.jsonl / tasks.jsonl（遥测，append-only）
                                │
                                ▼
                  离线脚本：拟合 → 验收门 → 原子替换 constants.json
```

边界规则（对齐"组件必须轻量"）：

- **组件运行时不读遥测文件**，只读 `constants.json`。
- 解析、拟合、校准检验、合成数据生成全部在离线脚本侧，那侧可用 scipy。
- 新增任何运行时依赖，必须先说明为什么不能放在离线侧。

技术栈：Python + numpy。可视化是一个自包含 HTML 文件，数据由离线脚本内联注入（见 §7 交付形态），自身不含统计代码。
理由：若把蒙特卡洛放到前端，需要自己实现泊松采样器（对数正体只是 `exp(正态)`，但泊松采样不平凡，约 60 行、含随机数发生器和分布函数），是纯粹的额外 bug 面。

## 3. 数学模型

### 3.1 生成模型（三层，不是一条回归方程）

总用时是一个复合随机和：

$$T=\sum_{j=1}^{J}\ \sum_{i=1}^{n_j} X_{j,i}$$

- **步长** $X_j \sim \mathrm{LogNormal}(\mu_j, \sigma_j^2)$。v1 取 $J=4$：`llm`（LLM 回合）、`tool`（工具调用）、`build`（构建/测试）、`net`（网络类操作）。
  选对数正体的理由有三条：恒正、右偏（一次工具调用通常 0.3 秒但偶尔 20 秒）、且"多一步"对时间是乘性影响而非加性；矩有闭式 $\mu_E=E[X]=e^{\mu+\sigma^2/2}$，$E[X^2]=e^{2\mu+2\sigma^2}$；**并且 $(\mu_j,\sigma_j^2)$ 的共轭先验正好是 Normal-Inverse-Gamma**，§3.5 的收缩因此是严格成立的而非近似。
  （注：本节初稿写的是 Gamma。Gamma 与 Normal-Inverse-Gamma 并不共轭——形状与速率两个参数未知时 Gamma 族没有闭式共轭先验，所以 §3.5 与 §3.1 在原稿下是互相矛盾的。换成对数正体同时解决矛盾并保留全部闭式矩。）
- **步数** $n_j \mid g \sim \mathrm{Poisson}(\lambda_j)$，$\lambda_j=\exp(\theta_j^{\mathsf T} g)$。
  这是计数数据的标准 GLM 形式，且 $n_j$ 在任务结束后可直接观测到真值，因此 $\theta_j$ 可拟合。
- **$g$ 只作为自变量。**LLM 猜"大概 6 次工具调用"，我们不采用这个数，只用它的分类档位去驱动 $\lambda_j$；$\theta_j$ 来自真实日志。这一步消除了"叙事性猜测"问题。

### 3.2 闭式矩与一条必须体现到 UI 的结论

$$E[T]=\sum_j \lambda_j e^{\mu_j+\sigma_j^2/2},\qquad \mathrm{Var}(T)=\sum_j \lambda_j e^{2\mu_j+2\sigma_j^2}$$

由复合泊松的方差公式 $\mathrm{Var}(\sum_{i=1}^{N}X_i)=\lambda E[X^2]$ 可得精确的相对不确定度：

$$\mathrm{CV}^2(T)=\frac{\sum_j\lambda_j e^{2\mu_j+2s_j^2}}{(\sum_j\lambda_j e^{\mu_j+s_j^2/2})^2},\qquad s_j^2=\sigma_j^2\max(\phi,1).$$

只有各类型步长服从同一分布、类别已确定时，才化简为 $\mathrm{CV}(T)=e^{s^2/2}/\sqrt{\bar n}$，其中 $\bar n=\sum_j\lambda_j$。原文的 $e^{\bar\sigma}/\sqrt{\bar n}$ 错把对数标准差与方差混用，且遗漏步长均值差异的条件。不能仅凭任务步骤更多就断定任意两类任务的相对区间一定更窄。

### 3.3 为什么参数化做在步级而不是任务级（统计效率论证）

任务级样本稀缺（一周可能只有几十个任务），用几十个点拟合几十个参数，系数的置信区间宽到没有意义。但步级样本天然稠密：一个任务就产生上百个 $X$ 观测。所以把 $(\mu_j,\sigma_j)$ 估计在数据稠密的步级、把语义猜测隔离在 $n_j$ 的回归里，是本模型严谨性的主要来源。

### 3.4 分位数计算

$T$ 明显右偏，**不允许用正态近似**。用蒙特卡洛：

- 对每条路径抽 $n_j\sim\mathrm{Pois}(\lambda_j)$，再抽 $n_j$ 个 $X\sim\mathrm{LogNormal}(\mu_j,\sigma_j^2)$（即 $\exp(\text{正体抽样})$），求和。
- v1 取 $m=5000$ 条路径，误差按 $1/\sqrt m$ 收敛，numpy 下毫秒级完成。
- 随机种子写入输出，保证可复现与可测试。
- 采样用 $\sigma_j\sqrt{\phi}$ 而非 $\sigma_j$，其中 $\phi$ 是 §9.1 的方差膨胀系数（$\phi=1$ 表示未启用）。

**贡献分解不用采样**，解析可得：$\text{share}_j=\lambda_j e^{\mu_j+\sigma_j^2/2}/E[T]$。

### 3.5 冷启动：共轭先验而非"手写猜测"

$(\mu_j,\sigma_j^2)$ 用 Normal-Inverse-Gamma 共轭先验（这正是对数正体步长下的严格共轭，见 §3.1）。先验表因此是一个**明确的先验假设 + 确定的收缩强度**，而不是没根据的数：某类操作无观测时输出先验预测区间；有观测后自动向数据收缩；每类的等效先验样本量是显式设定、可对外解释的。

初始先验给的是各类步长的**中位数**（即 $e^{\mu_j}$，单位秒）：`llm` 4、`tool` 1.5、`build` 90、`net` 3；$\sigma_j$ 的先验统一取 0.8，等效先验样本量取 20。这些是先验而非承诺，会随数据被覆盖。

**步数也需要先验**（本条为写实施计划时补上的缺口 —— 只给步长先验会让冷启动输出"每类操作只走 1 步"，第一个数就失真）。计数模型写成截距 + 被惩罚系数：

$$\lambda_j = \exp(b_j + w_j^{\mathsf T} x)$$

- $b_j$ **不受惩罚**，先验取 $b_j = \ln(\text{lambda0}_j)$，其中 `lambda0` = `llm` 8、`tool` 12、`build` 1.5、`net` 2（一次典型任务的步数量级）。
- $w_j$ 是 21 列的 ridge 系数，先验为全零 —— 即"不知道任何特征的影响"，随数据增长。
- one-hot 保留全部水平又存在自由截距时，二者会共线；这正是 ridge 把它压回先验的场景，因此**截距不受惩罚、系数受惩罚**是必需的分工，不是可调风格。

按上述先验量级，**中位数口径**的 $E[T]$ 粗算为 $8\cdot4+12\cdot1.5+1.5\cdot90+2\cdot3=191$ 秒（约 3 分钟），是一个合理量级的起点而非凑数。注意这只是文字量级：对数正体下 $E[X]=\text{median}\cdot e^{\sigma^2/2}$，所以模型真正的 $E[T]\approx263$ 秒。两个口径必须分清，实施计划里各有一条测试分别守住。

`calibrating` 标志的判据**唯一定义在 §6.5**（观测数阈值 + PIT 通过），本节的"某类观测为 0"只是它的一个特例，不另设规则。

### 3.6 分类噪声与协变量测量误差

LLM 分类会错，类别误判不保证无偏，也不保证只衰减回归系数。top-2 概率必须解释为任务类别的假设权重。其平均步数为：

$$\lambda_j = p_1 e^{\theta_j^{\mathsf T} g_1} + p_2 e^{\theta_j^{\mathsf T} g_2}$$

该等式只给出平均步数，不能用一个 $\mathrm{Pois}(\lambda_j)$ 替代类别混合。当前修正为每条采样路径先按 $p_c$ 选择一个任务类别 $C$，所有操作类型共享该类别，再按该类别采样步数和步长。总方差必须包括类别内与类别间两部分：

$$E[T]=\sum_c p_c M_c,\qquad \mathrm{Var}(T)=\sum_c p_c V_c+\sum_c p_c(M_c-E[T])^2.$$

运行时、PIT/覆盖率和配对验收使用同一个混合分布。分类概率是否可信仍须真实数据验证；不是增加一个数学混合就自动校准。

## 4. 特征向量 g

### 4.1 硬性规则

**LLM 输出分类档位，不输出数字。**数字从 LLM 出来属于伪精度（它会给出"6.5 次工具调用"这种它并不知道的数），而回归拿到一个带 500% 误差的连续自变量，比拿到一个正确的档位更糟。分类对 LLM 更容易，one-hot 后设计矩阵维度有界、可枚举。

### 4.2 v1 特征集（5 项，从完整的 9 项中裁剪而来）

| 特征 | 取值 | 主要驱动 |
|---|---|---|
| `task_class` | question / locate / patch / refactor / scaffold / debug / research | 全部（最强单因子） |
| `touched_files` | 1 / 2–3 / 4–10 / >10 | tool、build |
| `verification_loops` | 0 / 1 / 2 / >2 | build、**重试链** |
| `needs_network` | bool | net |
| `plan_steps` | 0 / 1–3 / 4–8 / >8 | 全部 |

one-hot 编码：$7+4+4+2+4 = 21$ 列，**保留全部水平、不 drop reference level**（drop 会让 ridge 惩罚对某一列不对称）；截距吸收进这一组水平里。$J=4$ 即 84 个 $\theta$ 参数。

`plan_steps` 若主 Agent 已列出 todo，直接数长度即可，**不需要额外模型调用**，且它是最强单因子之一。

`verification_loops` 是方差的主要来源（构建失败→重试），因此必须是显式特征，不能隐含在 `task_class` 里。

完整 9 项特征集（保留 `familiarity`、`needs_new_dependency`、`edit_kind`、`deliverable_form`）作为候选表，见 §6.3 晋级通道。

### 4.3 两条数据契约

1. **`g_schema_version` 必须进遥测记录。**取值集合一改，所有 $\theta_j$ 需重拟合；跨版本混样本会让权重静默失真。这是契约，不是可选元数据。
2. **$\theta_j$ 只能拿 `g_pred` 拟合，禁止用 `g_final`。**事后知道"实际改了 11 个文件"，但部署时没有这个信息；用 `g_final` 拟合得到的精度是虚高的，线上必然劣化。`g_final` 仅用于诊断"LLM 分类错在哪"。

## 5. 遥测

### 5.1 事件 schema（步级，append-only）

```json
{"v":1,"task_id":"t-042","op":"tool","t_start":1730000000.12,"t_end":1730000001.94,"ok":true,"tool":"grep"}
```

$X$ 与 $n_j$ 均为派生量，不落盘（存了就会与源不一致）。`ok:false` 保留，它是重试链的观测源。

### 5.2 任务记录 schema（任务级，一行一个任务）

```json
{"v":1,"task_id":"t-042",
 "g_pred":{"task_class":"patch","touched_files":"2-3","verification_loops":"2","needs_network":false,"plan_steps":"4-8"},
 "g_pred_probs":[["patch",0.62],["debug",0.31]],
 "g_final":{"task_class":"debug"},
 "total_wall":412.7,"censored":false,
 "model_id":"...","host":"...","estimator_wall":0.42,
 "g_schema_version":1}
```

分组键 `(model_id, host)` 由这两个字段派生，不另存 `env` 字段（存了就会和源不一致，同 §5.1 对派生量的处理原则）。`estimator_wall` 是预估器自身的耗时，为 §9.3 的自扰归因保留。

`model_id` 与 `host` 是漂移归因字段（"换模型"是头号漂移诱因，缺了这两个字段只能知道校准坏了、不知道谁弄坏的）。**推论：统一计算模型指结构统一，常数按 `(model_id, host)` 分组各存一套。**跨模型跨机器共用一套常数是该类估算最常见的失效方式。

### 5.3 接入源

v1 采用**合成数据先行**：schema 由模型反推定义，配一个合成数据生成器把全链路（拟合 → 采样 → 分位数 → PIT 校准）跑通并写满测试；真实源到位时只需新增一个 `parse(source_records) -> Iterator[StepEvent | TaskRecord]` 适配器，不碰模型一行代码。

合成生成器的定位不是占位符，而是**统计单元测试**：它按一组已知 $(\mu_j,\sigma_j,\theta_j)$ 生成数据，因此可以检验推断本身——拟合回来的参数应落在真值置信区间内，PIT 应通过 KS 均匀性检验，P90 带应覆盖约 90%。真实日志永远给不出"真值"，这个能力是合成数据独享的。

**必须避免循环自证**：生成器内置一套**与先验表不同的隐藏真值**。若生成器读的就是 `constants.json` 那套常数，测试必然通过、毫无信息量。

### 5.4 边界校验（只做三件，不多做）

enum 合法性、`t_end > t_start`、按 `(task_id, op, t_start)` 去重。违规事件写入 `rejects.jsonl` 留痕，**不允许静默丢弃**——被丢弃的往往是超长或异常那批，静默丢会让均值朝偏低方向系统性偏移，与删失同向。

## 6. 校准、重拟合与晋级门

重拟合**永远是离线显式命令**，不在运行时发生。自动重拟合带来权重抖动、不可复现、以及"一条坏日志把线上模型带跑"三种后果，均违背轻量要求。

### 6.1 触发门槛

每类操作新增有效观测 ≥ 50 才执行拟合；不足则拒绝并报告缺口数。

### 6.2 验收门（新版必须打赢旧版才能上线）

1. **时序 holdout，禁止随机切。**验证集取时间上最后的 $\max(20,\ 20\%)$ 个任务，其余用于拟合。随机切会因漂移而系统性高估精度（验证集用的是模型"没见过但时间上更早"的数据，线上不存在这种条件）。
   **启用条件：任务总数 ≥ 80，且拟合侧 ≥ 60。**84 个 $\theta$ 参数不可能从 20 个任务里拟合出来，低于此阈值时**不启用验收门**（此时配对比较的统计功效也不足以判成败），只做描述性 PIT 检查，且禁止自动上线。这条规则本身就是为了防止"用 12 个任务证明新版更好"。
2. **PIT 均匀性**：使用含并列值随机排序的预测秩，处理复合泊松在零处的原子；KS 检验 $p>0.05$。$\tau\in\{0.5,0.8,0.9\}$ 的分位数门检查 $P(Y<q_\tau)\le\tau\le P(Y\le q_\tau)$，经验比例加上 $2\sqrt{\tau(1-\tau)/n}$ 容差（$n$ 为验证任务数）。仅连续分布下才恢复原来的 $|coverage(\tau)-\tau|$ 双侧判据，不能错误要求离散上限覆盖率等于名义水平。
   容差**必须随 $n$ 走，不能定死成 0.05**：$n=20$ 时固定 0.05 约等于一个标准误，会频繁误杀本来合格的模型；而定死又会让它在 $n=500$ 时形同虚设。这条容差就是两个单侧标准差，既不过严也不过松。
3. **配对比较**：同一批验证任务上计算 pinball / 区间分数，候选版必须不劣于线上版。不配对比较无意义，两版面对的任务难度不同。
4. 通过 → **原子替换 + 保留旧版可回滚**；不通过 → 拒绝，线上不动。

评价区间预测器用**覆盖率**而非 MAPE：`p50/p90` 这个说法只有配上覆盖率才真的被验证或被证伪。

`constants.json` 带 `fit_id` 与 `trained_through_ts`，使每个历史 ETA 都能追溯到"当时用的是哪套常数"，否则事后无法解释误差来源。

### 6.3 扩容晋级通道

加操作类型 $J$ 或加 $g$ 特征，需同时满足：新类型观测达阈值、扩容后候选模型在配对 pinball 上**严格优于**当前模型、且校准仍通过。反向：连续两版打不赢则缩容。研究阶段提出的特征一律先进候选表，打赢了才进组件。

### 6.4 漂移检测

覆盖率分数本身就是探测器。滚动最近 100 个任务的 pinball 分数对基线做偏离检测（v1 用 2σ 规则，不做 CUSUM）。检出漂移后：加快历史数据折扣（EWMA 半衰期缩短），并让 UI 显示"可能过期"而不是继续给小数。

### 6.5 冷启动退出判据

在此前 `calibrating` 恒为真，判据两条同时满足：

- 每类操作的**步级观测数**（即 $X$ 的样本数，不是任务数）≥ 200；
- PIT 的 KS 检验通过。此处 ≥ 40 个任务是**描述性**检验的最低要求（关掉 `calibrating` 徽章的门槛），与 §6.2 验收门的 ≥ 80 是两件事：后者要同时喂饱拟合和 holdout，因此更严。任务数不足时本条自动判为未满足。

注意这两条的单位不同：前者数的是步，后者数的是任务。一个任务贡献几十到上百个步级观测，所以步级阈值通常远早于任务级阈值达成。

## 7. 可视化契约

**永不显示单独的数字。**呈现为 `大约 6–14 分钟` 的横向区间带，带宽即不确定性。依据 §3.2，短任务的宽带是诚实表达而非缺陷。

精度规则定死：分钟只显示整数；小于一分钟才显示秒；任何地方不得出现两位小数。

带下方是**贡献条**（`llm 45% / tool 30% / build 20% / net 5%`），来自 §3.4 的解析分解，可比区间带自信。

角落**状态徽章**三态：`校准中（数据还不够）` / `已校准 · 基于 N 个任务` / `可能过期（检出漂移）`。这是 §6 那套判据唯一面向用户暴露的地方。

**复盘视图**（任务结束后）：预估带与实际落点同轴呈现，落点在带内带外一眼可见——这是闭环唯一肉眼可见之处。其下是成绩单 `过去 100 个任务，90% 的带命中了 87 个`（即覆盖率检验），以及按 `task_class` 分组的误差表，指出下一步该给哪类任务补数据。

文案固定用"大约 / 预计区间"，禁止"将用时""预计完成时间"这类承诺措辞。

**交付形态**：由离线脚本把当次 JSON **内联注入**一个模板，产出一个自包含的 HTML 文件直接打开。不让页面运行时去 `fetch` 本地 JSON —— 浏览器对 `file://` 的本地 fetch 默认拦截，那样要么得起服务器、要么得改扩展，两件都不轻。内联注入把这个问题一次性消掉，同时保持"HTML 自身不含统计代码"。

## 8. 测试策略

- **参数回收测试**（合成）：已知真值 $(\mu_j,\sigma_j,\theta_j)$ 生成数据 → 拟合值须落在真值置信区间内；PIT 通过 KS。
- **非循环性检查**：断言生成器使用隐藏真值，且先验表 ≠ 生成器参数。
- **确定性测试**：固定种子 → 分位数输出逐位一致。
- **验收门拦截测试**：构造一个方差被故意压缩一半的候选常数表（看起来更自信、实为过拟合）→ 验收门**必须拒绝**。
- **漂移拦截测试**：在合成流中注入漂移点 → 探测器须在有限步内报警。
- **泄漏测试**：构造 `g_final` 与 `g_pred` 不一致的记录，断言拟合过程未读取 `g_final`。
- **极端输入快照**：`p50 == p90`（退化）与 `calibrating = true`（纯先验、零数据）两种输入下渲染不崩、且不显示虚假精度。
- **schema 校验测试**：三件边界校验各一条，含 `rejects.jsonl` 留痕断言。

## 9. 已知限制与偏误来源（显式记录，不假装解决）

1. **$n_j$ 与 $X_j$ 的独立性假设已知会低估方差。**构建失败触发重试，等于"这次构建慢"与"步数多"正相关。严谨解是建模重试链；v1 的兜底是一个标量方差膨胀系数 `phi`：
   - 由离线脚本从残差拟合（实际用时相对预测分布的过度分散程度），**$\phi \ge 1$ 为硬约束**；
   - 存进 `constants.json`，MC 采样时以 $\sigma_j\sqrt{\phi}$ 展宽各类型的对数标准差；
   - 它是全局一个数，不分操作类型——分类型估计需要更多样本，v1 不假装能做。
   这是残差驱动的启发式，并非相关性模型或精确矩匹配：相对残差方差比不等于对数方差倍率，且展宽对数方差会同时改变步长均值。真实的重试相关性是异质的，是否改善最终预测分布必须通过独立留出验证，不能保证一个全局标量吸收其平均效应。
2. **删失。**用户中途取消任务，真实用时只会比观测到的更长；当成完整观测会让估计系统性偏短。v1 处理按两张表分别决定，而不是整体丢弃或整体保留：
   - **步级表**：保留已完成步骤进入 $(\mu_j,\sigma_j)$ 拟合；尚未结束的步骤不是完整时长。若取消机制与时长相关，完整步骤也可能存在选择偏差，不能无条件称为无偏观测。v1 没有实现完整的生存/删失模型。
   - **任务级回归**：$n_j$ 在此类任务里只是下界，**不进 $\theta_j$ 的泊松回归**。
   这样既避免了"当作完成"导致的偏短，也没有把有效信息扔掉。整体丢弃会白丢大量步级观测，整体保留会让均值偏低，两者都不可接受。
3. **并行预估器的自扰。**预估器与主 Agent 并行运行，若底层 API 有速率限制，它会把主 Agent 拖慢，而它又要预测那个被它拖慢的时间。v1 处理：给预估器独立配额或独立小模型，并在任务记录里保留其自身耗时以便归因。
4. **收敛慢是真实预期。**84 个 $\theta$ 参数需要数百个任务才能压出有意义的区间；在此之前输出主要由先验驱动。这不是缺陷，但意味着早期数值的参考价值有限——UI 的 `calibrating` 徽章必须长期存在，不得为了"看起来准"提前关闭。
5. **MAPE 类指标不作为验收依据。**点估计的平均百分比误差无法区分"自信的错"和"诚实的宽"。

## 10. 产物清单（v1）

- `constants.json`：分组到 `(model_id, host)`，含 $(\mu_j,\sigma_j)$、$\theta_j$、方差膨胀系数 $\phi$、等效先验样本量、每类步级观测数、`fit_id`、`trained_through_ts`、`g_schema_version`。
- 组件运行时：`g → λ → 蒙特卡洛 → {p50, p90, contributions, calibrating, seed, schema_version}`，纯函数、无状态、无 HTTP、无数据库。
- 存储：两个 append-only JSONL + 一个 `rejects.jsonl`。无数据库。
- 可视化：一个静态 HTML，消费上述 JSON 输出。
- 离线脚本：合成生成器、适配器接口、拟合、验收门、漂移检测。
