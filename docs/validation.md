# 验收记录

本文记录可复现的验收事实。所有数字来自合成遥测或独立数值实验，**不是**真实 Agent 的预测准确率。
根目录 `constants.json` 是冷启动先验；合成拟合表只写进被忽略的 `data/` 与 `out/`。

## 2.5 闭环验收：hook → 遥测 → 重拟合

`examples/record_telemetry.py --tasks 120` 走的是产品真正要走的路径：任务由 `ElapsedHooks`
计时、`TelemetryRecorder` 落盘（每 7 个任务制造一次取消）、然后自动尝试一次 `refit`。
合成任务的步数与步长带抖动（泊松步数、对数正态步长），否则每个任务一模一样，
任何带离散度的模型都会被判"过覆盖"。

| 项目 | 结果 |
|---|---|
| 记录任务 / 步事件 | 120 / 1574 |
| 完整任务（取消记删失） | 103（17 个删失） |
| 时间序切分 | 拟合 82 / 验证 21 |
| 验收门 | accepted |
| 覆盖率 P50 / P80 / P90 | 0.571 / 0.905 / 1.000 |
| PIT KS p | 0.494 |
| 拟合 φ | 1.67 |
| 不可用记录 | 0 |

这条链路暴露过一个真实的统计缺陷，已修（详见 [math-upgrade.md](math-upgrade.md) §7.5）：
位置先验给 20 个伪观测时，285 个真实观测之后中位数仍被拉高 33%，覆盖率冲到 1.0、KS 拒绝，
新宿主的第一次重拟合永远过不了门。位置与尺度解耦后同一批数据即被接受。

## 3. 运行时性能抽查

单次 5000 路径预估（先验表、Python 3.14 / numpy 2.4、本机）：均值约 **5 ms**，
同一次预估自带的分位数标准误 `p90_se` ≈ 7.6 s（真值表下 P90 区间约 ±89 s）。
这是本地测量，不是性能保证；宿主需要的是"几毫秒算完一条任务"，这个量级满足，
但如果宿主想缩小 P90 区间，代价是线性增加路径数。

## 4. 展示门控

`python3 examples/tui_host.py --plain --interval 0.05` 可复现：

- 普通聊天与短任务：不出现组件；
- 显式长任务（未校准表）：显示 `任务进行中 · 已用 0 秒 · 校准中`，**不显示**先验区间；
- 取消后组件移除，宿主记录 `cancelled`。

HTML 复盘页数据内联、无外部资源；曾在 390 像素视口下检查无横向溢出（截图产物不入库）。
